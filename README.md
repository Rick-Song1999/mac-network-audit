# macOS 网络风险监测

一个原生 SwiftUI 网络与环境风险监测工具，独立于 Claude 或其他代理客户端。面向 macOS 13 及更新版本，当前 Xcode 项目配置为 Apple Silicon（arm64）。应用以当前用户权限运行，不需要管理员权限、Python、额外框架或后台守护进程；它不会启动或管理其他应用，也不会修改代理、DNS、路由、时区或系统地区设置。

[English README](README.en.md) · [第三方来源与授权](THIRD_PARTY_NOTICES.md)

## 获取与构建

此仓库提供源代码，并在 [GitHub Releases](https://github.com/Rick-Song1999/mac-network-audit/releases) 提供 Apple Silicon（arm64）预览版压缩包。该版本为 ad-hoc 签名，未进行 Developer ID 公证；首次运行可能被 macOS Gatekeeper 拦截。也可使用 Xcode 16 或更新版本自行构建：

1. 打开 `MacNetworkAudit.xcodeproj`。
2. 选择 `MacNetworkAudit` scheme 和本机作为运行目标。
3. 点击 Run，或使用 Product → Build 构建。

最低部署版本为 macOS 13。项目当前只配置 Apple Silicon（arm64）。本地生成的应用和压缩包位于 `build/`，不会提交到 Git 仓库。

## 界面语言与图标

- 首次启动默认跟随 macOS 系统语言；在“设置 → 界面语言”中可固定为简体中文或 English。选项会保存在本机，下次启动继续使用。
- 主界面、设置项、状态和检测结果说明均支持中英文切换。
- 应用图标采用深蓝底色与银蓝网格地球，并以青色连线表示网络路径。

## 检查项

| 检查 | 方法与边界 |
|---|---|
| 代理进程 | 只读进程列表，发现常见代理客户端时标记为风险信号；进程存在不证明所有流量都经过该代理 |
| TUN 网卡 | 查看活动隧道接口；发现代理或隧道时计为风险信号，需结合出口 IP 和路由判断 |
| 出口 IP | 查询 Cloudflare Trace，失败时回退到 ipinfo.io |
| IP 一致性 | 对比本机最近 48 小时记录，只在 IP 变化时保存记录 |
| 时区 | 将系统时区与出口 IP 的地区时区比较，也检查手动填写的预期时区 |
| 系统地区与语言 | 将系统地区和语言偏好中的地区代码与出口国家 / 地区比较；只有语言代码而没有地区代码时不推断位置 |
| Mac 销售地区型号 | 只读取 Apple 平台地区代码；`CH/A` 按中国大陆销售渠道标记风险，`LL/A` 按非中国销售渠道显示通过，不与系统预期国家比较。其他代码无法确认时保持待判断。地区码只是销售渠道参考，不表示电脑当前所在地，也不是购买凭证 |
| 设备位置与 IP 位置 | 需要单独点击该行按钮并允许 macOS 定位服务；一次性近似位置只在内存中与 ipinfo.io / ipapi.co 的 IP 位置对比，不会发送或保存设备坐标。仅显示约略距离；定位或 GeoIP 误差、来源不一致时显示无法判断，远距离也不等于已确认泄漏 |
| IPv6 | 使用 IPv6 专用出口探测；检测到 IPv6 不等于泄漏，需配置预期地区才可比较归属 |
| DNS 隧道 | 使用系统 DNS 查询用户指定的域名，并与预期 Fake-IP 网段比较 |
| WebRTC | 对 Google 与 Cloudflare STUN 节点发送 UDP Binding 请求，比较映射地址与 HTTP 出口；节点响应不完整时不报通过 |
| 路由规则 | 查看用户指定域名的 DNS / Fake-IP 表现，一次最多 20 个；无法读取代理控制器策略组，也不验证最终选路 |
| IP 网络类型与运营商 | 分别显示可获取的 IPv4 / IPv6 地址的 ISP、组织、ASN 和第三方住宅宽带、移动网络或数据中心分类；分类结果不证明物理接入方式 |
| IP 信誉风险 | 分别显示可获取的 IPv4 / IPv6 地址的 IPfastcheck 风险值和代理、VPN、Tor、托管、欺诈、滥用、诈骗及封禁清单标记。高风险条件与服务方判定规则一致；低分不代表没有风险，也不是通用安全评分 |
| 站点可达性 | 对用户配置的 HTTPS 地址发起 HEAD 请求，不跟随 HTTP 跳转；收到 HTTP 响应表示连接可达，不代表服务功能可用 |
| 大陆出口归属 | 比较 Cloudflare Trace、ipinfo.io 与 ipapi.co 的出口地区标记；至少两个可用来源一致才显示结果。CN 表示中国大陆，HK/MO/TW 单独显示；结果描述公网 IP 归属，不证明机器物理位置 |
| 双栈出口 | 分别获取 IPv4 与 IPv6 出口并比较地区。地址不同本身不代表泄漏；缺少任一地址或地区证据时显示无法判断 |
| DNS 解析器路径 | 手动全检时从 dnsleak.dev 获取一次性随机主机名，通过 macOS 系统解析器查询，再读取权威端观察到的解析器分组。split 显示需留意，no_leak 只表示本轮未观察到分流，部分结果或服务状态异常均显示无法判断 |
| 路由画像 | 只读读取 macOS `scutil --dns`、到固定公共 IPv4/IPv6 目标的路由接口和 `scutil --proxy`。系统代理和经隧道接口的公网路由作为风险信号显示；这些证据不能单独证明所有流量的实际路径 |
| WebKit 环境 | 手动全检时在应用内嵌 WKWebView 中读取语言、时区、平台和 STUN `srflx` 映射；与 macOS 和 HTTP 出口对照。只描述本应用的 WebKit 环境，不代表 Safari / Chrome，也不显示私有或 mDNS 候选地址 |

DNS 隧道、路由规则和站点可达性需要在“设置”中填写对应输入。站点可达性默认使用 Cloudflare，用户可更换为自己的 HTTPS 测试站点。未配置或服务未响应会显示“待配置”或“无法判断”，不会算作通过。

IPfastcheck 字段、风险分段和记录缓存说明参见 [API 文档](https://ipfastcheck.com/api)。

## 监测与本地数据

- 支持手动检测，也支持持续监测；默认每 60 秒，设置范围为 30 秒至 15 分钟。
- 手动“立即检测”执行常规和深度检查。持续监测只运行快速检查，DNS 解析器与 WebKit 深度检查会保留上次结果和时间；设备位置比较必须单独点击该行按钮并授权，不会随手动全检或定时监测启动。
- 关闭主窗口或停止监测会停止计时器和当前检测。
- 设置写入当前用户的 macOS 偏好设置。
- IP 变化历史存放在 ~/Library/Application Support/MacNetworkAudit/egress-history.json，最多保留 48 小时，并可从主窗口清除。首次检测先建立基线，因此 IP 一致性会显示“无法判断”。
- IPfastcheck 的成功响应在应用内存中缓存 24 小时，失败响应缓存 15 分钟，避免定时监测重复查询；结果详情分别显示服务记录日期和本机取得资料时间。其接口文档说明 IP 记录可能在服务端缓存最长 180 天。
- 子进程探测有硬超时；停止监测或清除历史会取消当前检查，清除时等待活动周期结束后再删除记录。
- 不上传检测报告。Cloudflare Trace、ipinfo.io、ipapi.co、ipify 和 IPfastcheck 会看到当前请求涉及的公网出口 IP；IPfastcheck 查询可用的 IPv4 / IPv6 地址，接口文档说明其记录可能缓存最长 180 天。手动 DNS 检测把随机主机名查询发送到 dnsleak.dev；该服务可看到出口 IP 和向其权威服务器发出请求的解析器地址，其 API 说明测试结果在内存中保留十分钟。STUN 探测访问 Google 与 Cloudflare STUN。设备位置比较只在用户单独点击并授权后启动 macOS 定位服务；设备坐标不上传、不保存，仅在本机内存与 IP GeoIP 估算位置比较。DNS 与 WebKit 探测详情只保留在当前应用内存中，不写入 48 小时 IP 历史。
- 风险等级结合本机观测和第三方 IP 资料；它不是通用安全评分，也不预测特定网站的处理结果。IP 地区、网络类型和风险分均可能不准确。
